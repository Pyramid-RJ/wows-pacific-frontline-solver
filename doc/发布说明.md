# 发布说明 · 三种发布形态

求解器本体是一套 Python 源码 + 数据（`code/` `data/`）。为了让不同的人都能用上，
发布时打成三种形态；三者**内容完全同源**，都来自 `git archive HEAD`，
差别只在「有没有自带运行环境」和「怎么交付」。

| 形态 | 产物 | 收包方要做什么 | 体积 |
| --- | --- | --- | --- |
| 批处理版 · 不含初始环境 | `太平洋战线求解器-批处理版-不含环境_日期.zip` | 自备 Python 3.10+，双击 `安装环境.bat` 联网装依赖 | ~3 MB |
| 批处理版 · 含初始环境 | `太平洋战线求解器-批处理版-含环境_日期.zip` | 解压即用（不装 Python、不联网） | ~110 MB |
| exe 版（图形门户·绿色版） | `太平洋战线求解器.exe` / `太平洋战线求解器-exe版_日期.zip` | 双击出图形门户，点入口即可 | ~110 MB |

---

## 一、怎么打

四个脚本（都在仓库根目录，用开发环境的解释器跑）：

| 脚本 | 作用 |
| --- | --- |
| `打包公共.py` | 公共逻辑：`git archive` 取发布内容、打 zip、校验成品 |
| `打包批处理版.py` | 打两种批处理包 |
| `exe启动器.py` | exe 的图形门户源码（被 `打包exe版.py` 冻结成 exe） |
| `打包exe版.py` | 打单文件 exe（图形门户） |

```bat
.venv\Scripts\python 打包批处理版.py              :: 不含环境 + 含环境
.venv\Scripts\python 打包批处理版.py --light      :: 只打「不含环境」
.venv\Scripts\python 打包批处理版.py --full --selftest
.venv\Scripts\python 打包批处理版.py --deep       :: 自检 + 端到端演练（整套求解，约 2 分钟）
.venv\Scripts\python 打包exe版.py                 :: 单文件 exe（自动实测：门户 + 回归 + 演练）
```

产物都落在 `dist/`（`dist/` 已在 `.gitignore` 里，不入库）。

另有历史脚本 `打包发布.py`，等价于「批处理版 · 不含环境」，产物名是老的
`太平洋战线求解器_日期.zip`；保留是为了不打断既有引用。

> **打包工具、`doc/发布说明.md`（本文件）本身不进发布包** ——
> 它们在 `.gitattributes` 里标了 `export-ignore`。发布包只放收包方要用的东西：
> 免得在**批处理**包里出现 `exe启动器.py`、`打包exe版.py` 之类让人犯嘀咕的文件，
> 也免得别人拿本文件当使用说明（各形态的说明随包自带：批处理「含环境」版有
> `本包已内置运行环境-请先看这个.txt`，exe 版有 `使用说明.txt`）。

### 发布内容的唯一来源

`打包公共.py` 用 `git archive HEAD` 取内容 —— 也就是说**发布包 = 该提交的跟踪文件**，
再由 `.gitattributes` 里的 `export-ignore` 瘦身。所以：

* 想改发布内容，改文件并提交即可，不用维护白名单；
* 想改「哪些文件不进发布包」，改 `.gitattributes` 的 `export-ignore`
  （现有的：示例大图、规则手册配图、`.docx`、评估标注集、打包工具、本文件）。

打完后脚本会**校验成品 zip**：关键文件必须齐（缺一即失败），
且不得混入本地产物（`data/plan.json`、`player_input.json`、`__pycache__`、
`doc/figures/` …）。

## 二、三种形态各自的关键设计

### 1. 批处理版 · 不含初始环境

就是 `git archive` 的内容。收包方见 `使用说明.md` 第一章：装 Python →
双击 `安装环境.bat` → 拖文件夹到 `求解整局.bat`。

### 2. 批处理版 · 含初始环境

要自带运行环境，但不能直接拷本机 `.venv`：**Windows 的 venv 不可搬迁**。
`.venv/Lib/` 里只有 `site-packages`，标准库在基础 Python 安装目录
（`pyvenv.cfg` 的 `home`），换台机器就找不到解释器了。

所以打包时这样拼（见 `打包批处理版.py` 的 `build_runtime()`）：

```
.venv/Scripts/   官方「嵌入式发行版」Python 3.12 解在这儿
                 python.exe / python312.dll / python312.zip(标准库) / 扩展 .pyd
                 + msvcp140.dll / concrt140.dll（cv2、onnxruntime 要）
                 + python312._pth ← 把依赖与 code/ 接到解释器上
.venv/Lib/site-packages/   依赖（本机 .venv 里回归验证过的那一套）
```

`python312._pth` 的内容：

```
python312.zip
.
..\Lib\site-packages
..\..\code
import site
```

这样 `.venv\Scripts\python.exe` 这个路径没变，**现有 5 个 `.bat` 一行都不用改**。

嵌入式发行版从 `mirrors.huaweicloud.com` 取（python.org 直连在国内常被重置），
缓存在 `.work/pkg/pyembed.zip`。`._pth` 要用 `write_bytes` 写 ——
Windows 下 `write_text` 会把 `\n` 翻成 `\r\n`。

包内额外放一份 `本包已内置运行环境-请先看这个.txt`：本包不需要装 Python、
不需要联网；`安装环境.bat` 是给「不含环境」版用的，在本包里跑它会找不到系统
Python，那不是故障。

### 3. exe 版（图形门户 · 绿色版）

`exe启动器.py` 就是一个 **tkinter 图形门户**，用 PyInstaller
`--onefile --windowed` 冻结成单个 exe（`--windowed` = 不要黑框控制台）。
内嵌解释器 + 依赖（含 OCR 引擎与模型）+ 整个发布内容。

门户上六个入口（都跑在后台线程，输出实时打进窗口下方的日志区）：

```
整局求解   选一个装着整局截图的文件夹，自动按阶段分组逐关求解 → 求解完自动开面板
单阶段求解 只求解当前一个阶段
查看方案面板 打开图形面板，看每个据点的编队、变项与胜率
编写输入   起本地服务 + 打开浏览器，填「有哪些卡 / 战损格数 / 阶段 / 变项库存」
自检       门户自检 + 求解层回归 + 端到端演练，结果写 自检报告.txt
打开运行目录 结果与面板都在该目录的 data\ 里
```

**绿色版（非安装）**：首次运行把内嵌内容铺到 **exe 所在目录**，
之后整个软件就是「这个 exe + 它旁边那几个文件夹」，拷到 U 盘就能走，
不写注册表、不装任何东西。exe 所在目录不可写时（例如放在 `Program Files`）
自动退回 `%LOCALAPPDATA%\太平洋战线求解器`，窗口顶部显示实际位置；
也可用环境变量 `PZ_SOLVER_HOME` 指定别处。玩家自己的东西
（`plan.json` / `player_input.json` / `player_state.json` …）升级时永不覆盖。

**为什么不在 exe 里直接冻结 `code/`**：`code/` 下所有模块都用
`ROOT = Path(__file__).resolve().parent.parent` 定位 `data/`。冻结后 `__file__`
指向 PyInstaller 的临时解包目录，`ROOT` 会算到临时目录外面，`data/` 就找不到了。
把 `code/` 落在磁盘上、用 `runpy` 按真实路径执行，`ROOT` 永远指向运行目录。

同理，内嵌内容不是用 `--add-data 目录` 塞进去的（PyInstaller 对目录落点的语义
容易踩坑），而是先打成 `_payload.zip`，运行时按清单解出来。

窗口模式下没有控制台，两件事要自己兜住（都在 `exe启动器.py` 里）：

* `sys.stdout` / `sys.stderr` 换成转发流 → 子脚本的 `print` 进窗口日志区；
* `sys.stdin` 换成非交互对象（`isatty()` 为假）→ 万一走到 `input()` 走 EOF 分支，
  而不是卡死。

### 4. 三种形态都有的：不给用户的控制台入口

exe 版**没有面向用户的命令行**（图形门户就是全部界面）。只留两个打包/排障入口：

```bat
太平洋战线求解器.exe --selftest      :: 无窗口跑自检，写 自检报告.txt，按结果给退出码
太平洋战线求解器.exe home|version    :: 打印运行目录 / 版本
```

`--selftest` 是**打包脚本的验收口**：窗口模式的 exe 没有 stdout 可抓，
只能看它写出来的 `自检报告.txt` 与退出码。

## 三、验收（每次打发布版都该跑）

```bat
:: 1. 求解层回归（开发环境）
.venv\Scripts\python code\test_m5.py

:: 2. 批处理版 · 含环境：用「包内运行时」跑自检
.venv\Scripts\python 打包批处理版.py --full --selftest
::    --selftest 用 stage\.venv\Scripts\python.exe 导入
::    numpy/PIL/cv2/onnxruntime/rapidocr_onnxruntime，并跑 code\test_m5.py
::    加 --deep 再跑一遍 examples\solve_demo.py（不依赖截图的整套求解，
::    末行应为「整局汇总：5 阶段 · 13 据点 · 未达标 0 个」）

:: 3. exe 版：打包脚本自带实测
.venv\Scripts\python 打包exe版.py
::    会把 exe 内容解到 .work/pkg/exe_home，跑 求解器.exe --selftest，读 自检报告.txt，
::    要求报告里同时出现：图形门户：正常 / 全部通过 / 未达标 0 个
```

三种形态都**真的跑一遍自检**才算过。尤其 exe：**图形门户也进自检** ——
真把 tkinter 窗口构造出来、泵一段事件循环、再关掉；不然「打包成功但窗口起不来」
会一路发到用户手上。

### 已知的验收边界

自检**不覆盖识别层**（OCR / 模板匹配）。识别回归是 `code/test_all.py`，
它要读 `data/stage/*.jpg` 这些游戏截图，而截图在 `.gitignore` 里、**刻意不进发布包**，
所以发布包里跑不了它。要覆盖识别层，得先在仓库里跑：

```bat
.venv\Scripts\python code\test_all.py      :: 识别层 28/28
```

## 四、发出去之前

* `git status` 必须干净（发布内容取自 `git archive HEAD`，未提交的改动进不了包）。
* 关键数据（`data/our_fleet.json`、`data/var_config.json`、
  `data/player_input.template.json`、`data/stage/glyph_tpl.npz`、
  `data/weak_templates.json`、`data/type_glyphs/`、`data/weak_ref/` …）都在跟踪中，
  改完记得提交，否则发布包里还是旧的。
* `.gitattributes` 里的 `export-ignore` 是「哪些文件不进发布包」的唯一开关。
* 打 exe 要往 `.venv` 临时装 PyInstaller。打完记得卸掉，让 `.venv` 回到基线
  （`打包批处理版.py` 另有一道构建工具过滤 + 成品校验兜底，但保持基线更省事）：

  ```bat
  .venv\Scripts\python -m pip install "pyinstaller>=6.0"
  .venv\Scripts\python 打包exe版.py
  .venv\Scripts\python -m pip uninstall -y pyinstaller pyinstaller-hooks-contrib ^
      altgraph pefile pywin32-ctypes setuptools
  ```
