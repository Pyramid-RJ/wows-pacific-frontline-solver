## 待发布 · 2026-10-13（第二批：识别 + 关底预留）

> 标题待定（建议 v0.3）。这批是 v0.2 打包**之后**的改动，尚未进任何发布包，
> 打包前记得**重跑回归**（`test_all` / `test_m5` / `test_m3b` / `test_stage_own`
> + 用整局截图跑一次 `--all`）。

### 这次修了什么

v0.2 之后又拿玩家的实拍截图对了几轮：改掉三处**识别错误**、加了一个
**保证关底达标的求解机制**。识别那三处都是「静默出错」—— 程序不报错、
照样给方案，只有对着面板逐格核对才发现。

1. **新舰种「驱逐舰」的禁用图标认不出来（光板旗）**

   面板「禁用的单位类型」用的就是舰名旁那面**舰种旗**（纸面上是深色版；
   旗标文件是反相版）：**无斜纹＝驱逐舰**、1 道斜纹＝巡洋舰、2 道＝战列舰。
   原先只有巡洋舰 / 战列舰 / 飞机三个模板，光板旗被巡洋舰模板抢走（0.70 胜出）。

   现在补上驱逐舰模板 —— **由旗标反相推导**（玩家那张截图只有 1280 宽、
   图标仅 15×7 像素，斜纹都糊了，拿实拍裁剪反而做不出模板）：新模板对
   实拍图标得分 0.83，高于巡洋舰的 0.70。文件：`data/type_glyphs/ban_驱逐舰.png`。

2. **面板可以有「多行」禁用的单位类型 —— 旧版只读第一行**

   一个据点的禁用分别挂在 `带入` / `区域` / `指定` 段下，各禁各的。旧版只读
   **第一行**（玩家实拍那份第一行正好是「带入」段）→ **区域段的禁用根本没被
   看过**，玩家看到的就是「区域明明禁了战列舰和驱逐舰，程序照样上驱逐舰」。

   现在逐行识别、逐行记住挂在哪一段；**只有「区域」段拦人**（与其它条件的口径
   一致：全胜后带入 / 指定的条件会消失），其它段照样列出来但标
   「（带入 段），不生效」。另外**图标认不出时一定会提示**（旧版静默跳过 ——
   这正是这个问题能藏那么久的原因）。

3. **双斜纹的战列舰被读成单斜纹的巡洋舰**

   同一份实拍里，区域内那枚战列舰图标的匹配分数是「巡洋舰 0.81 ＞ 战列舰 0.78」，
   **只差 0.03**：IoU 被旗形的**轮廓**主导，1 道与 2 道斜纹在归一化（还会拉伸
   纵横比）之后几乎分不出来。

   现在先数**斜纹道数**再比形状：旗形内部的空白段＝斜纹，0 道＝驱逐舰、
   1 道＝巡洋舰、2 道＝战列舰（并要求「出现 2 道的行数 ≥2」以避开噪声孔）。
   同时加了「形体分族」（实心旗 vs 飞机那副细臂十字）—— 没有这层，新的实心
   驱逐舰模板会把飞机的机影抢走（实测 0.56 ＞ 0.53，会让「巡洋舰+飞机」变成
   「巡洋舰+驱逐舰」）。全部实拍图标按 ASCII 逐个人工判读建了真值表，新判据
   25/25 全对（旧判据错 2 处，都是战列舰）。

4. **敌方战力首位「1」丢失**（143 → 43、149 → 49，顺带代币读成空）

   一排 4 张敌方卡里**两张**带掉落徽章时，卡列宽度量出来是
   `[274, 208, 274, 214]`；旧版拿**中位宽**当参考宽度，4 个数取上中位恰好落在
   **274** → 阈值 315 → 一个都不截 → 卡头窗口整体右移，首位数字被挤出窗口，
   而且**不报低置信**。

   现在参考宽度取**最窄**那一列（徽章只会往列的右侧加宽、不会让它变窄），
   另外先把**右侧面板**那段浅色区域从列扫描里剔掉（面板底面也是浅色、会被当成
   卡列，实测有样本的第 5 段 248px 就是面板纸面）。修完这张图读数是
   `143/145/149/141`，两枚代币从空值恢复成 `90/75`。

5. **新机制：关底预留 —— 先算关底要哪几张卡，前面各阶段一律禁用**

   整局口径是「每卡每阶段一次、参战一次 −1 格」：前面阶段把关底要用的卡用掉
   一次，关底拿到的就是**带伤**的那张（实测能把关底从 100% 打到 48%）。
   旧的「等级治理」只保护 3 级舰，挡不住「关底需要的恰好是 2 级卡」。

   现在一上来**先把关底阶段单独算一遍**（全部卡按满血），看它需要哪几张卡；
   然后**它之前的所有阶段一律禁用这几张卡**，正向重跑 —— 关底那几张卡必然
   满血到场，**事前**锁住关底，不必等失败了再回退重算。

   * 报告里会写：`【关底预留】阶段 5 先单独算一遍……它要用 4 张卡 →
     阶段 1、2、3、4 一律禁用这些卡（牌名）`；
   * 被禁的阶段在「需人工确认」里标「本阶段禁用了关底预留的 N 张卡」；
   * 关底在**全卡满血**下都算不到目标胜率时**不做预留**（预留救不了它，只会
     白白削弱前面阶段），照常求解并如实报未达标；
   * 旧的「关底失败 → 前面阶段改强制省卡 → 整段重跑」**默认关闭**了
     （命令行 `--boss-rollback` 可开回来），现在默认走事前预留。

   实测（1945「主力部队」行动 13 个据点）：**新默认 13/13 全部达标**（两次复跑
   一致）；旧模式仍是「阶段4 据点8 只到 81%」。1945 的 GOLF / ROMEO 两个行动
   同样 7/7 全达标。机制上，预留扣住的 4 张强卡也让前序阶段的配牌重新分配，
   原先让据点8 落弱卡的那处争用消失了。

### 已知问题（如实列出）

* 「关底预留」取的是**关底所在阶段整段**用到的卡（同阶段据点共用卡池、血量
  接力都在阶段粒度上）。关底阶段据点多、而关底只用 4 张时，扣住整段的卡会让
  前面阶段紧一些 —— 遇到具体局再考虑收紧到「只锁关底那一关」。
* `strong_perm_attack` 的排列搜索有 4 秒挂钟预算，理论上同一输入在不同机器上
  可能给出不同结果（本批各局两次复跑一致，未观察到摆动）。
* 潜艇 / 航空母舰还没有面板实拍，禁用图标遇到这两个舰种会认不出或认错 ——
  用 `banned_types` 人工补录（认不出时程序会提示）。
* golf 行动 据点3 的「禁用的单位类型」挂在**指定**段，按现行口径（只有「区域」
  段的禁用生效）不折算。玩家已确认**指定段管的是后续的指定关**，全胜打法下与
  本关无关，故口径不变。

## v0.2 · 2026-10-13

> 与 v0.1 是同一个工具的两个版本，装一个即可。三种下载形态说明见文末。

### 这次修了什么

v0.2 主要是**识别与折算的准确性**修复 —— 都是拿实拍截图逐格对出来的，
会直接影响推荐编队与预期胜率：

1. **「带入」的敌方战力加成不再被当成敌方的初始战力**（影响最大）

   面板上带「带入」加成的敌舰战力会显示成**绿色**，那是**已经加成过**的值；
   而进入战斗时游戏用的是**未加成的基础值**（以部署界面上的数字为准）。
   用实拍核对：主力部队据点8 面板绿字 173 / 178 / 151 / 170，
   部署界面 160 / 165 / 140 / 157 —— 正好差 8%，而减益步长仍是干净的 −20%。
   旧版直接拿面板绿字当基础值，这些据点被系统性高估 8%（推荐了偏强的阵容）。

   现在程序按 **`基础值 = 面板值 ÷ (1 + 带入加成)`** 反推，并在该据点下多打一行
   对照（`面板绿字显示 […] ，已按「带入」敌方战力加成 +8% 反推出基础值`）。
   宣告该条件的那一关（挂在**全域 / 指定**段）不受影响、也不反推 —— 已用实拍确认
   （主力部队据点5、ROMEO 据点4 的面板值与部署界面完全一致）。

2. **区域「火力 −X%」被整条漏读 → 已修复**

   条件小字**整块**识别时会把「火力」读成「力」，于是那一行只剩百分比、
   属性名丢失，被静默跳过（等于火力被高估）。现在会把该行**单独裁窄带、按原始
   分辨率重读**补回来，并在「需人工确认」里提示抽检一次。

   实测受影响的据点：主力部队 据点2（火力 −24%）、据点9（火力 −8%）、
   mygame_s4 关底（−24%）、mygame_s5 阶段3 据点10（−12%）。

3. **「敌方战力 +X%」不再被误算成我方的「战力 +X%」**

   面板上「火力 / 存活性 / 机动性 −X%」与「战力 −X%」是**我方**被削弱，
   「敌方战力 +X%」是**敌方**被增强 —— 两行两回事。旧版按名字子串匹配，
   把后者读成前者，一旦它落在「区域」段，我方参数会凭空虚增 8%。

4. **少用特殊变项**（新机制）

   理由：**特殊变项只能靠战斗奖励获得（一次性），而卡牌每次行动都会恢复状态**
   —— 所以能用卡解决的就不该花特殊变项。现在若「整段一门特殊变项都不花」
   也能做到**同样多**的达标据点，程序就改用那一版（多花几张卡、把特殊变项省下来）；
   卡池撑不住时自动回到原方案，不会牺牲达标。

   实测（同一份截图、同一套卡）：golf 阶段2 特殊变项 **6 → 0**、
   romeo 阶段2 **1 → 0**、mygame_s1 阶段2 **10 → 0**，达标据点一个没少。

5. **「效率提升」写清口径**：任何**奖励为进度代币**的据点都吃它的 +10%
   （不是只有关底 BOSS）。程序本来就是逐据点装的，这次只把说明与注释里
   那句「只有关底掉落」的错误前提改掉。

6. **禁用单位类型的图标模板改名**：`ban_飞机_2` 画的其实是**巡洋舰**，
   已改名。此前它从未在样本里胜出、没造成误判，但换个面板渲染就可能把
   巡洋舰读成飞机。

7. **提示与面板更清楚**
   * 新增「面板绿字 ≈ 基础值」对照行（命令行 + 图形面板都显示）；
   * 条件行属性名是靠重读补出来的，会在「需人工确认」里标「建议抽检一次」；
   * 「几何印章判定与条件文字并存」这类**已知误报**，提示语改成
     「以文字为准、只需抽检」，不再像报错。

### 已知问题（如实列出）

* **主力部队 阶段4 据点8**：现在算到 81%（其余 12 个据点都是 100%）。
  这不是数据错 —— 程序内验证过「阶段4 五个据点全 100% 的解**是存在的**」，
  是阶段内搜索的「等级治理」这条路径没找到它。
  **规避办法**：用「单阶段求解」只跑阶段4，或在「编写输入」页把本阶段的
  变项库存填一下（那份截图没有工具栏，特殊变项按 0 库存处理）。
* 「**区域**」段的「敌方战力 ±X%」按「区域 = 永久生效」推算为战斗加成 ——
  目前没有任何实拍样例，属**未验证分支**。
* golf 行动 据点3 的「禁用的单位类型」挂在**指定**段：按现行口径（只有
  「区域」段的禁用生效）不折算。若你在游戏里发现它确实拦人，请告知，这条口径要改。
* 绿色掉落牌（特殊变项掉落，如 🔧 快速维修）上的数字会被 OCR 读成乱码并标
  「代币读数低置信」—— 程序按设计只认进度代币，这些噪声不影响任何决策。

### 三个下载形态

| 文件 | 说明 |
| --- | --- |
| `wows-pacific-frontline-solver-v0.2-exe.zip` ⭐ | **推荐**。解压后双击 exe 即可，**不用装 Python、不用联网**；绿色版，拷到 U 盘 / 换电脑都能直接用 |
| `wows-pacific-frontline-solver-v0.2-batch-with-env.zip` | 批处理方式，**已内置运行环境**，解压即用（包较大） |
| `wows-pacific-frontline-solver-v0.2-batch-without-env.zip` | 批处理方式，体积最小；需自备 **Python 3.10+**，首次先双击 `安装环境.bat`（约 100MB 依赖，需联网一次） |

三种形态**内容同源**，都来自同一份源码；差别只在有没有自带运行环境、以及怎么交付。

### 怎么用

1. **截图** —— 每个据点的地图 / 部署界面截一张（游戏窗口 1920×1080 及以上最佳）。
2. **求解** —— exe 版点「整局求解」选截图文件夹；批处理版把文件夹拖到 `求解整局.bat` 上。
3. **看方案** —— 求解完自动打开图形面板。

> **第一次使用前先点「编写输入」**：卡牌默认按「全部拥有」处理，
> 把**自己没有的卡**取消勾选即可。

截图要求、字段说明、结果解读与常见问题，详见包内 `使用说明.md`。

## v0.1 · 2026-10-12

首个发布版：识别（截图 → 据点数据）+ 求解（编队 / 变项 / 胜率）全链路打通，
支持整局多阶段求解、跨阶段战损接力、图形面板与三种交付形态。
