# 弱点图标标注集

人工标注的真值数据，供 `code/m8v.py`（弱点识别 v2）评估使用。

## 目录结构

```
data/weak_labeled/
├── truth.json          # 真值标注（本目录的权威文件）
├── images/             # 被标注的截图
│   ├── 1.png ~ 5.png
│   └── README.md
└── (旧文件已清理)
```

## 真值格式（truth.json）

```json
{
  "classes": { "smoke": "烟雾", "atkair": "攻击机", ... },
  "images": {
    "1.png": [["smoke","rapid"], ["rapid","atkair"], ...],
    ...
  }
}
```

`images` 的键是 `images/` 下的文件名；值是**按截图内卡牌顺序**排列的标注，
每个元素是该张卡的弱点图标列表，**按卡内从左到右**。

共 5 张截图 / 20 张卡 / **39 枚图标**。

注：5.png 第 2 张卡只有 1 枚图标。

**规则（用户确认）：每张敌方卡有 1 或 2 个弱点 —— 至少 1 个，最多 2 个。**
因此识别端不应假定恒为 2 枚，而要能判定「槽 2 是否存在徽章」。

术语统一：用户口语「烟雾/烟幕」→ `smoke`；「侦查/侦察」→ `detect`。

## 当前评估结果（2026-10-10，`code/m8b_weak.py`）

**定位 20/20 卡 · 检出 39/39 枚 · 分类 39/39 = 100%，零混淆。**

复现：`python code/test_m3b.py`（含参数平台扫描，约 5 秒）

### 前一版为何只有 44%

早期 README 把原因写成「符号倾斜 30~45°」。**该结论已被实测否定**：
把图标裁片放大后，符号是**正置**的，与 40×40 标准图标同形同向。
真正的三处原因都是工程问题：

| # | 问题 | 修法 |
| --- | --- | --- |
| 1 | 卡片定位用「顶部 42% 亮带 + 宽度 40~300px」，相邻卡连成 340px 超宽 run 被丢弃（4.png 只切出 1 列） | 改用**底部文本条**亮列投影（卡宽恒 255px、间距 440px） |
| 2 | 掩膜把徽章外环圈进来 —— 外环在 4 个方位有**浅色缺口**（rr≈0.83），掩膜被污染成「环 + 符号」 | 径向只取 `rr ≤ 0.60`，并**只保留最大连通域** |
| 3 | 用**圆盘归一化**比较（查询 R≈26 vs 模板 R=19.5，符号占比被拉偏） | 改为**按符号 bbox 归一化** |

### 参数平台（不是刀尖上的参数）

`lim ∈ [0.55, 0.63] × thr ∈ [140, 200]` 全部 39/39；
归一化边长 20~48 全部 39/39。
失效边界：`lim ≥ 0.70` 且 `thr ≤ 160` 时徽章外环漏入掩膜，会掉到 40% 以下。
