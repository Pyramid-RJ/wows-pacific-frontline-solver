## 掉落物口径

**只识别进度代币，判据是圆牌是否为金色**（饱和度 ≥ 0.22）。

⚠ **不能用数量级判断**：经验值、硬币等掉落物同样落在 1k~2k，
`s2_kp4` 卡面的「硬币柱 1600/2000/2400」就长得像大额代币但不是进度代币。

| 类别 | 圆牌饱和度实测 |
| --- | --- |
| **进度代币（金色圆牌：同心环 + 三角徽记）** | **0.319 ~ 0.448** |
| 次级代币（银色圆牌） | 0.067 ~ 0.126 |
| 硬币柱（`s2_kp4` 卡面） | 0.075 ~ 0.091 |
| 灰色箱体（`s2_kp5` 卡面） | 0.067 ~ 0.081 |

次级代币与其余掉落物**一律忽略、不参与任何决策**。

`无进度代币` 的据点不装「效率提升」；只要识别到进度代币就**必须**装
（唯一跳过理由是库存或次级货币不足，会显式告警）。

## 怎么跑

```bash
cd solver
PY=.venv/Scripts/python

# 阶段 1（3 个据点，全屏截图）
cat > /tmp/in_s1.json <<'EOF'
{"stage": {"current": 1, "total": 4}, "secondary_uses_max": 1,
 "missing_cards": [], "damaged_cards": {}}
EOF
$PY code/m11_plan.py --input /tmp/in_s1.json \
    --shots s1_kp1 s1_kp2 s1_kp3 --stage-dir data/stage_own

# 阶段 2（2 个据点）
cat > /tmp/in_s2.json <<'EOF'
{"stage": {"current": 2, "total": 4}, "secondary_uses_max": 1,
 "missing_cards": [], "damaged_cards": {}}
EOF
$PY code/m11_plan.py --input /tmp/in_s2.json \
    --shots s2_kp4 s2_kp5 --stage-dir data/stage_own

# 阶段 3（1 个据点）
$PY code/m11_plan.py --input /tmp/in_s3.json \
    --shots s3_kp6 --stage-dir data/stage_own

# 阶段 4（关底 BOSS，掉落进度代币 → 必装「效率提升」）
$PY code/m11_plan.py --input /tmp/in_s4.json \
    --shots s4_kp7 --stage-dir data/stage_own
```

`--shots` 只写文件名（不含扩展名），扩展名不限（`.png/.jpg/.jpeg/.webp/.bmp` 自动匹配）。

**跨阶段战损接力（实测阶段1 → 2 → 3 → 4）**：程序默认把每阶段结束后的生命值写进 `data/player_state.json`
（`--state` 可改路径，`--no-state` 关闭）。所以跑完阶段 1 再跑阶段 2，
阶段 1 参战过的 12 张卡会自动以 `hp2` 参与阶段 2 的编队 —— 实测阶段 2 输出里
可直接看到 `hp2`，这就是「上一阶段战损已计入」的证据。

## 为什么这批图重要（UI 缩放）

玩家截图的 UI 缩放**不是 1920 基准**（阶段1 为 2375 宽 = 1.23×），
若直接喂给按 1920 标定的识别常量，战力会读成 `None`、端到端直接崩溃。
`m2_layout.load_screen()` 在**入口**做等比归一化解决此问题；
本目录是唯一能同时验证「归一化 + 整屏弱点入口」的样本，**不要删**。
